The lab — one release file, one fictional noticeboard, nobody else's machines
====================================================================

The lab is Telegraf as InfluxData ships it: the official
release file telegraf-1.40.3_linux_amd64.tar.gz (84 MB,
SHA-256 cbb95c43303db6e75e129a4eb8888ab1468009e61f6615e64a1cb82f50b0f4ce)
from dl.influxdata.com, unpacked under the batch scratch
folder and run from there on the build machine (an Ubuntu
24.04 sandbox) rather than installed system-wide. Nothing
was installed, no service was started. Drivers find the
binary through TELEGRAF_BIN, falling back to the scratch
path they were built with, then to a telegraf on PATH.

  * The fixture project (fixtures/): a community
    "noticeboard" with three invented sensors — two
    temperature sensors in hall-a and hall-b and a door
    counter in a lobby — written as one JSON array in
    readings.json. The agent's hostname in every config
    is the invented "boardwalk-01", with invented global
    tags project=noticeboard and site=pier-a where a
    config uses them. Generic, invented, and nobody's
    real project.

  * Configs (configs/): system.conf (cpu/mem/system to a
    file, gather and flush 2s), fixture.conf (the JSON
    fixture through the json parser and a rename
    processor), http.conf (http_listener_v2 on
    127.0.0.1:18083 to a file), stats.conf (the same
    listener through basicstats, 5s period, originals
    dropped), flush.conf (cpu, gather 1s, flush 3s), and
    broken.conf (an input plugin that does not exist,
    on purpose). All paths inside configs are relative
    to telegraf-lab/; every driver stands there first.

  * Driver scripts (drivers/): common.sh plus one per
    test, t00 to t07. Live runs are bounded with
    timeout(1) so counts mean something; timeout's exit
    124 on a live run is success and the transcripts
    say so. Outputs land in outputs/, which is runtime
    scratch and not evidence.

  * Every claim's evidence (transcripts/): t00 version,
    the full --help, a generated sample config and one
    plugin's --usage; t01 config check, --test (5 points,
    1/1/3) and --once (the same 5, written); t02 the live
    9-second run (24 lines: 4 cpu, 5 mem, 15 system);
    t03 the fixture parsed in --test and --once (tags
    chosen, field renamed); t04 the listener (204 in,
    point out; 400 for a malformed line); t05 basicstats
    (10/20/30 in, one summary line out); t06 flush
    batching (0, 0, 0, 0, 2, 2, 2, 6, 6, 6, 9, then 10
    on shutdown flush); t07 both broken configs and
    their exact errors.

  * Kept in the record: Telegraf 1.40.3 prints two
    startup warnings in every transcript (strict
    environment handling; a processor-ordering default
    changing in v1.41.0). They were left in the evidence
    and explained in chapters 3, 10 and 15 rather than
    edited out. The t02 counts are untidy (4/5/15)
    because real timers are untidy; chapter 6 explains
    instead of rounding.
